# Sayo Sense 完整部署与上架手册

这份手册是总入口，面向第一次部署的开发者。你不需要一次看懂全部内容，按阶段执行即可：

1. 先确认源码和图标已经提交到 GitHub。
2. 再部署云服务器，让手机和电脑能通过 HTTPS 访问 API。
3. 然后分别生成 Windows 安装包、Android 包和 iOS 包。
4. 最后做真机验收，再提交应用商店。

> 这是一份操作手册，不代表当前工作区已经完成云服务器部署、正式签名或商店上架。涉及云端实测、真机录音、文件选择器、签名和审核的项目，必须按文中步骤亲自验收。

---

## 一、先看你最终要得到什么

### 1. 云端服务

最终应有一个自己的域名，例如：

```text
https://app.example.com
```

手机、网页和电脑端通过它访问后端：

```text
https://app.example.com/api/v1
```

服务器内部建议运行：

```text
Caddy（服务器宿主机，负责 HTTPS）
        |
        v
Docker Compose
  ├─ Nginx / H5
  ├─ FastAPI
  ├─ MySQL 8
  ├─ Redis 7
  └─ uploads Volume（原件、图片、音视频）
```

### 2. 三个客户端

| 客户端 | 产物 | 生成机器 |
| --- | --- | --- |
| 手机浏览器 / H5 | 云端网页 | Ubuntu 服务器 |
| Android | `app-release.aab` 或 `app-debug.apk` | Windows 或 macOS |
| iPhone / iPad | 签名后的 IPA / TestFlight 构建 | macOS + Xcode |
| Windows 电脑端 | `Sayo-Sense-Setup-1.0.0.exe` | Windows |

Android 调试包不能直接当作正式商店包。iOS 的正式签名、TestFlight 和 IPA 也不能在 Windows 上完成。

## 三、阶段 0：先把源码准备好

### 1. 在 Windows 开发机上检查改动

在项目根目录打开 PowerShell：

```powershell
git status --short
```

确认 `.env`、`keystore.properties`、`.jks`、`.p12`、`.p8` 和 `.mobileprovision` 没有出现在待提交列表中。

提交本次需要发布的源码：

```powershell
git add README.md docs branding scripts desktop-app mobile-app
git commit -m "完善 Sayo Sense 品牌图标与部署文档"
git push origin master
```

如果当前分支不叫 `master`，使用：

```powershell
git branch --show-current
git push origin 当前分支名
```

不要使用 `git add -f` 强行上传密钥文件。云端和 Mac 只能拿到已经推送到 GitHub 的代码。

### 2. 明确哪些东西绝对不能进 Git

以下文件只保存在自己的密码管理器和离线备份中：

- `.env`
- MySQL 密码
- `SENSITIVE_FIELD_KEY`
- `DEEPSEEK_API_KEY`
- Android `keystore.properties`
- Android `.jks` 或 `.keystore`
- Apple `.p12`、`.cer`
- `.mobileprovision`
- `AuthKey_*.p8`

服务器上的 `.env` 只通过 SSH 或云厂商控制台编辑，不通过聊天、截图或公开日志发送。

## 四、阶段 1：在 Ubuntu 云服务器部署后台

详细命令可对照：[云端部署教程](云端部署教程.md)。

### 1. 购买服务器

小白内测建议：

- 系统：Ubuntu 24.04 LTS
- CPU：4 核起步
- 内存：8 GB 起步
- 磁盘：100 GB SSD 起步
- 带宽：按团队人数和上传文件大小选择
- 地域：优先选择离实际用户近的地区

SenseVoiceSmall、OCR、Docker 首次构建和语音模型会占用较多 CPU、内存和磁盘。团队人数更多或上传大量视频时，建议 8 核 16 GB，并单独规划数据盘。

如果服务器在中国大陆，域名和公网服务通常需要按当前规定完成 ICP 备案；否则 80/443 可能无法正常使用。香港或海外服务器不需要同样的备案流程，但访问速度、数据合规和供应商条款要自行确认。

### 2. 准备域名

在域名服务商处新增 DNS 记录：

```text
类型：A
主机记录：app
记录值：云服务器公网 IPv4
最终域名：app.example.com
```

在本地 PowerShell 检查：

```powershell
nslookup app.example.com
```

返回的 IP 必须是这台服务器。DNS 可能需要几分钟到数小时生效。

### 3. 云安全组和防火墙

只开放：

| 端口 | 用途 |
| --- | --- |
| 22 | SSH 管理 |
| 80 | HTTP，申请 HTTPS 证书 |
| 443 | HTTPS |

不要对公网开放 MySQL `3306`、Redis `6379`、FastAPI `8000` 或内部 Web `8080`。

登录服务器：

```bash
ssh root@你的服务器公网IP
```

更新系统：

```bash
sudo apt update
sudo apt upgrade -y
sudo apt install -y ca-certificates curl git nano ufw unzip
sudo timedatectl set-timezone Asia/Shanghai
```

### 4. 安装 Docker 和 Docker Compose

使用 Docker 官方安装脚本：

```bash
curl -fsSL https://get.docker.com -o /tmp/get-docker.sh
sudo sh /tmp/get-docker.sh
sudo systemctl enable --now docker
docker --version
docker compose version
```

如果当前不是 root 用户：

```bash
sudo usermod -aG docker $USER
newgrp docker
docker ps
```

### 5. 下载项目

```bash
sudo mkdir -p /opt/asset-library
sudo chown -R $USER:$USER /opt/asset-library
cd /opt/asset-library
git clone https://github.com/Arvin665/-app-.git .
```

如果目录里已经有自己的文件，不要直接覆盖。先换一个空目录，或确认现有文件可以保留。

如果本机刚改了代码还没有推送，服务器执行 `git pull` 也拿不到。必须先在 Windows 完成提交和推送。

### 6. 创建生产配置

```bash
cd /opt/asset-library
cp deploy/.env.production.example .env
nano .env
```

至少替换这些值：

```dotenv
MYSQL_ROOT_PASSWORD=一段很长的随机数据库根密码
MYSQL_DATABASE=mall_office_asset
MYSQL_USER=asset_user
MYSQL_PASSWORD=一段很长的随机应用数据库密码
WEB_BIND=127.0.0.1
WEB_PORT=8080
SENSITIVE_FIELD_KEY=至少32位的随机密钥
BOOTSTRAP_INVITE_CODE=六位数字初始邀请码
PUBLIC_BASE_URL=https://app.example.com
CORS_ORIGINS=https://app.example.com,https://localhost,capacitor://localhost
```

生成随机密钥：

```bash
openssl rand -base64 48
openssl rand -base64 48
openssl rand -base64 48
```

生成六位初始邀请码：

```bash
shuf -i 100000-999999 -n 1
```

注意：

- `PUBLIC_BASE_URL` 不要带最后的 `/`。
- `CORS_ORIGINS` 用英文逗号分隔。
- `https://localhost` 给 Android Capacitor 容器使用。
- `capacitor://localhost` 给 iOS Capacitor 容器使用。
- `BOOTSTRAP_INVITE_CODE` 只在第一次没有管理员时使用，绑定成功后系统会停用它。
- `SENSITIVE_FIELD_KEY` 以后不要随意更换，否则已加密字段可能无法读取。

### 7. 配置 DeepSeek

在 `.env` 中增加或修改：

```dotenv
AI_PROVIDER=auto
DEEPSEEK_API_KEY=sk-你的真实Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_TIMEOUT_SECONDS=90
```

说明：

- `DEEPSEEK_BASE_URL` 不要写成 `https://api.deepseek.com/v1/chat/completions`，后端会自动拼接 `/chat/completions`。
- `deepseek-chat` 是当前项目默认的通用对话模型标识，适合结构化提取、纠错和计划拆分。模型名称可能变化，以 DeepSeek 控制台当前可用列表为准。
- `deepseek-reasoner` 可用于更强的推理，但通常更慢、成本更高，不建议一开始替代默认模型。
- 不配置 Key 时，系统应退回本地规则，不能因此丢失原始语音和文件。
- 不要把 Key 放前端、Dockerfile、GitHub Actions 明文或微信聊天。

修改 `.env` 后必须重建后端：

```bash
cd /opt/asset-library
docker compose up -d --force-recreate backend
docker compose logs --tail=100 backend
```

检查接口：

```bash
curl https://app.example.com/api/v1/health
```

应用内“关于系统”或 AI 状态接口应显示：

```text
deepseek_configured=true
```

如果仍显示 `false`，按顺序检查：

```bash
cd /opt/asset-library
grep -E '^(AI_PROVIDER|DEEPSEEK_BASE_URL|DEEPSEEK_MODEL)=' .env
docker compose exec backend printenv AI_PROVIDER DEEPSEEK_BASE_URL DEEPSEEK_MODEL
docker compose up -d --force-recreate backend
docker compose logs --tail=100 backend
```

不要输出完整 API Key。只检查变量是否存在即可。

### 8. 第一次启动

全新空数据库不需要手动导入表：

```bash
cd /opt/asset-library
docker compose config
docker compose up -d --build
docker compose ps
```

首次构建可能需要下载 Python 依赖、FFmpeg、SenseVoiceSmall 和 Vosk 模型，耗时会明显长于后续升级。

查看日志：

```bash
docker compose logs -f backend
```

按 `Ctrl+C` 只退出日志查看，不会停止服务。

检查本机入口：

```bash
curl http://127.0.0.1:8080/api/v1/health
```

正常应包含数据库状态 `ok`。如果 Redis 报错：

```bash
docker compose restart redis backend
docker compose logs --tail=100 redis
```

### 9. 用 Caddy 配置 HTTPS

```bash
sudo cp /opt/asset-library/deploy/Caddyfile.example /etc/caddy/Caddyfile
sudo nano /etc/caddy/Caddyfile
```

把 `app.example.com` 改成你的真实域名，然后：

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
sudo systemctl status caddy --no-pager
```

验证：

```bash
curl -I https://app.example.com
curl https://app.example.com/api/v1/health
```

如果证书申请失败，检查 DNS、80/443 安全组、Caddy 日志和端口占用：

```bash
nslookup app.example.com
sudo ss -lntp | grep -E ':80|:443'
sudo journalctl -u caddy -n 200 --no-pager
```

### 10. 首次登录

打开：

```text
https://app.example.com
```

用 `.env` 中的 `BOOTSTRAP_INVITE_CODE` 绑定第一个管理员。绑定成功后立即：

1. 检查个人中心。
2. 生成新的设备邀请码。
3. 设置有效期和使用次数。
4. 让团队成员用新邀请码绑定。
5. 确认普通成员看不到他人的私有工作记录和个人灵感。

移动端如果显示 `request:fail`，先在手机浏览器打开：

```text
https://app.example.com/api/v1/health
```

浏览器打不开时先修域名、HTTPS、防火墙或后端，不要反复猜邀请码。

### 11. 已有数据库的升级

已有的生产数据库不要再执行完整 `init.sql`，它会删除旧表。先备份，再执行迁移：

```bash
cd /opt/asset-library
mkdir -p backups
docker compose exec -T mysql sh -c \
  'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines --events "$MYSQL_DATABASE"' \
  > "backups/before_migration_$(date +%Y%m%d_%H%M%S).sql"
```

然后按 `backend/app/database/migrations/` 的文件顺序执行新增迁移。

### 12. 备份和恢复

手动备份：

```bash
cd /opt/asset-library
chmod +x scripts/backup.sh
./scripts/backup.sh
```

每天自动备份：

```bash
crontab -e
```

加入：

```cron
30 2 * * * cd /opt/asset-library && ./scripts/backup.sh >> $HOME/asset-library-backup.log 2>&1
```

至少保留：

- 最近 30 天每日备份
- 每月一份长期备份
- 每次升级前一份手动备份
- 一份服务器磁盘之外的异地备份

不要执行 `docker compose down -v`，`-v` 会删除 MySQL、Redis 和上传文件卷。

## 五、阶段 2：生成 Windows 电脑端安装包

Windows 端单独使用 Electron 打包，不是 Android 或 iOS 的替代品。

在开发机进入桌面端：

```powershell
Set-Location .\desktop-app
npm.cmd ci
npm.cmd run dist:win
```

安装包输出大致在：

```text
desktop-app\release\Sayo-Sense-Setup-1.0.0.exe
```

当前已经接入：

- `desktop-app/build/icon.ico`：安装包和快捷方式图标
- `desktop-app/build/icon.png`：构建辅助图标
- `desktop-app/electron/assets/app-icon.png`：窗口图标
- `desktop-app/electron/assets/tray-icon.png`：托盘图标

如果打包报错：

1. 确认 Node.js 是 20 或 22 LTS。
2. 确认 `desktop-app/node_modules` 已安装。
3. 删除 `desktop-app/release` 后重试，不要删除源码。
4. 检查 `desktop-app/package.json` 的 `build.directories` 和 `win.icon` 是否仍然存在。

如果错误包含 `Cannot create symbolic link`，这是 Windows 权限问题，不是源码问题。可以在 Windows 设置中打开“开发者模式”后重启，或用管理员身份的 PowerShell 重新执行 `npm.cmd run dist:win`。


正式签名前，Windows 安装包可能出现“未知发布者”。这是正常现象，不等于图标或程序损坏。若要做正式发布，需要另外购买代码签名证书，并按证书厂商教程配置。

## 六、阶段 3：Android 上架前准备

详细步骤见：[Android 内测与正式发布](安卓发布教程.md)。

### 1. 安装环境

在 Windows 上安装：

- Android Studio
- Android SDK 和 Platform-Tools
- JDK 21 或 Android Studio 当前推荐 JDK

检查：

```powershell
java -version
adb version
```

### 2. 配置生产 API 地址

在 `mobile-app` 目录：

```powershell
Set-Location .\mobile-app
$env:VITE_API_BASE_URL = 'https://app.example.com/api/v1'
npm.cmd ci
npm.cmd run build:h5
npx cap sync android
```

正式包不能使用 `127.0.0.1`，因为手机上的 `127.0.0.1` 指手机自己。

### 3. 生成签名密钥

在 `mobile-app/android` 目录执行：

```powershell
keytool -genkeypair -v `
  -keystore asset-library-release.jks `
  -alias asset-library `
  -keyalg RSA `
  -keysize 2048 `
  -validity 10000
```

然后：

```powershell
Copy-Item '.\keystore.properties.example' '.\keystore.properties'
notepad '.\keystore.properties'
```

填入真实密码。`asset-library-release.jks` 和 `keystore.properties` 必须离线备份，不能上传 Git。

### 4. 生成调试包

```powershell
Set-Location .\mobile-app
npm.cmd run native:sync:android:debug
npm.cmd run native:build:android:debug
```

调试包路径：

```text
mobile-app\android\app\build\outputs\apk\debug\app-debug.apk
```

安装到已开启 USB 调试的 Android 手机：

```powershell
adb devices
adb install -r '.\android\app\build\outputs\apk\debug\app-debug.apk'
```

### 5. 生成正式 AAB 和 APK

在 `mobile-app/android` 中：

```powershell
.\gradlew.bat bundleRelease
.\gradlew.bat assembleRelease
```

产物：

```text
mobile-app\android\app\build\outputs\bundle\release\app-release.aab
mobile-app\android\app\build\outputs\apk\release\app-release.apk
```

检查签名：

```powershell
apksigner verify --verbose '.\app\build\outputs\apk\release\app-release.apk'
```

看到 `Verifies` 才表示签名可被识别。

### 6. 提交 Google Play

1. 注册并验证 Google Play Console 开发者账号。
2. 创建应用，名称填写 `Sayo Sense`。
3. Package name 保持 `com.shcredible.sayo`。
4. 填写图标、截图、简介、分类和隐私政策 URL。
5. 按真实情况填写 Data Safety：设备 ID、音频、照片/文件、用户内容等。
6. 先上传 `app-release.aab` 到 Internal testing。
7. 按测试链接安装，完成至少一次真机录音、文件导入、计划确认和提醒验收。
8. 测试通过后再提交 Production。

国内应用市场通常还需要企业主体、软件著作权/权属材料、隐私政策和备案信息，要求各不相同，以各商店后台为准。

## 七、阶段 4：iPhone / iPad 上架前准备

详细步骤见：[iPhone 内测与 App Store 发布](苹果发布教程.md)。

### 1. 必备条件

- 一台 macOS 电脑
- Xcode
- Apple Developer Program 账号
- iPhone 真机
- 已解析并可公网访问的 HTTPS 域名

Windows 只能准备源码，不能生成正式 IPA。

### 2. 在 Mac 上拉取并构建

```bash
mkdir -p ~/Projects
cd ~/Projects
git clone https://github.com/Arvin665/-app-.git asset-library
cd asset-library/mobile-app
npm ci
export VITE_API_BASE_URL="https://app.example.com/api/v1"
npm run build:h5
npx cap sync ios
npx cap open ios
```

### 3. Xcode 设置

1. 选择蓝色工程 `App`。
2. 选择 `TARGETS -> App`。
3. 打开 `Signing & Capabilities`。
4. 勾选自动签名。
5. 选择自己的 Team。
6. 确认 Bundle Identifier 与 `mobile-app/capacitor.config.js` 中的 `com.shcredible.sayo` 一致。
7. 确认 `Version` 和 `Build`，每次上传 Build 必须递增。

如果 Bundle ID 已被其他账号占用，改成自己团队唯一域名，并同时修改：

- Xcode 的 `PRODUCT_BUNDLE_IDENTIFIER`
- `mobile-app/capacitor.config.js` 的 `appId`

App 发布后不要随意修改 Bundle ID。

### 4. TestFlight

真机运行确认后：

1. Xcode 选择 `Any iOS Device (arm64)`。
2. `Product -> Archive`。
3. Organizer 中选择 `Distribute App`。
4. 选择 `App Store Connect -> Upload`。
5. 到 App Store Connect 等待 Processing。
6. 添加 Internal Testers。
7. 用 TestFlight 安装，完成录音、文件、关联记录、今日待办、后台提醒和深链接测试。

### 5. 提交 App Store

准备：

- 1024 × 1024 不透明图标
- 真实功能截图
- 隐私政策公开 URL
- 支持 URL
- 年龄分级和审核问卷
- 审核专用邀请码
- 审核测试数据和操作步骤

审核备注要说明这是商办业务工具，并提供：

- 原生录音和后台上传识别
- 相机、相册和系统文件导入
- 本地通知
- 设备邀请码和团队权限

## 九、常见故障速查

### 登录显示 `request:fail`

先在手机浏览器打开：

```text
https://你的域名/api/v1/health
```

浏览器也失败：修域名、HTTPS、安全组或后端。

浏览器成功但 App 失败：检查 `VITE_API_BASE_URL`、是否重新构建并 `npx cap sync`，以及 `CORS_ORIGINS` 是否包含 `https://localhost` 和 `capacitor://localhost`。

### 修改 DeepSeek 后仍显示未配置

```bash
cd /opt/asset-library
docker compose up -d --force-recreate backend
docker compose exec backend printenv AI_PROVIDER DEEPSEEK_BASE_URL DEEPSEEK_MODEL
curl -sS https://你的域名/api/v1/ai/status -H "X-Device-ID: 你的设备ID"
```

如果变量不对，继续修改服务器根目录 `.env`；不要在 `backend` 子目录再建一个没有挂载的 `.env` 期望它自动生效。

### 图标显示旧版

1. 重新运行图标生成脚本。
2. 清理浏览器缓存。
3. Android 执行 `npm.cmd run native:sync:android:debug` 后重装。
4. iOS 删除模拟器 App 后重新运行。
5. Windows 卸载旧版本后重新安装新安装包。
6. 商店图标必须在对应后台重新上传，不能只改网页 favicon。

### 云端磁盘满

```bash
df -h
docker system df
docker compose logs --tail=100 backend
```

只清理确认不再需要的旧镜像，不要删除 `mysql_data`、`redis_data` 或 `uploads_data`。

### Windows 安装包找不到

检查：

```powershell
Get-ChildItem .\desktop-app\release
```

如果没有安装包，重新执行：

```powershell
Set-Location .\desktop-app
npm.cmd run dist:win
```

## 十、建议的实际上线顺序

1. 在 Windows 提交并推送源码。
2. 购买域名和 Ubuntu 服务器，完成 DNS。
3. 部署后台，验证 HTTPS 和 `/api/v1/health`。
4. 生成 Windows 安装包，先在自己电脑测试。
5. 生成 Android Debug APK，在真实 Android 手机测试。
6. 修复真机问题后生成正式 AAB。
7. 在 Mac 上生成 TestFlight 构建并测试 iPhone。
8. 准备隐私政策、截图、审核邀请码和商店资料。
9. 先内测，再提交正式审核。

最小可执行的下一步：先在 Windows 项目根目录执行 `git status --short`，确认没有 `.env` 或签名文件后，把当前代码提交到 GitHub，再开始购买或登录云服务器。
