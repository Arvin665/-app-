# iPhone 内测与 App Store 发布教程

这份教程面向第一次发布 iOS App 的人，按顺序操作即可。

本项目当前信息：

- 应用名：`Sayo Sense`
- Bundle ID：`com.shangban.assetlibrary`
- iOS 工程：`mobile-app/ios/App/App.xcodeproj`
- 前端目录：`mobile-app`
- 最低系统：iOS 15
- 原生外壳：Capacitor 8
- 后台接口示例：`https://app.example.com/api/v1`

> 正式签名、真机安装、TestFlight 和 App Store 上传必须在 macOS + Xcode 上完成。Windows 只能修改代码和准备材料，不能生成可上架的 IPA。

## 一、先完成后台部署

iPhone 必须能通过公网 HTTPS 访问后台。先完成《云端部署教程》，然后在 Mac 或 iPhone 的 Safari 打开：

```text
https://你的域名/api/v1/health
```

应看到：

```json
{"status":"ok","database":"ok"}
```

服务器 `.env` 的跨域白名单必须同时包含网页、安卓和苹果容器：

```dotenv
CORS_ORIGINS=https://你的域名,https://localhost,capacitor://localhost
```

其中：

- `https://你的域名`：浏览器 H5。
- `https://localhost`：Android Capacitor 容器。
- `capacitor://localhost`：iOS Capacitor 容器。

修改后重启后端：

```bash
cd /opt/asset-library
docker compose up -d --force-recreate backend
docker compose logs --tail=100 backend
```

## 二、准备 Apple 账号和 Mac

### 1. 注册 Apple ID

准备一个长期可用的 Apple ID。建议开启双重认证。

### 2. 决定发布方式

- 只在少量内部人员中测试：先用 TestFlight。
- 需要长期公开下载：加入 Apple Developer Program，再通过 App Store 发布。
- 仅公司内部使用：查看 Apple Business Manager 的 Custom Apps 或 Unlisted App Distribution，以 Apple 当前政策为准。
- 免费 Personal Team 只适合短期真机调试，不适合 TestFlight 和正式上架。

开发者年费、审核规则和地区要求可能调整，以 Apple Developer 官网和 App Store Connect 当前显示为准。

### 3. 安装 Xcode

在 Mac 的 App Store 安装最新稳定版 Xcode，然后执行：

```bash
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -license accept
xcodebuild -version
open -a Xcode
```

第一次打开 Xcode 时，完成组件安装，并登录：

```text
Xcode → Settings → Accounts → 添加 Apple ID → Manage Certificates
```

如果 Xcode 提示安装额外组件，按提示安装。

### 4. 安装 Node.js

安装 Node.js 20 或 22 LTS。检查：

```bash
node -v
npm -v
```

## 三、在 Mac 上取得项目

代码必须先推送到 GitHub，或从 Windows 完整复制到 Mac。

如果从 GitHub 下载：

```bash
mkdir -p ~/Projects
cd ~/Projects
git clone https://github.com/Arvin665/-app-.git asset-library
cd asset-library/mobile-app
```

如果最新改动还没有上传 GitHub，服务器和 Mac 都拿不到这些改动。先在开发电脑完成提交和推送，再执行这里的下载。

安装依赖：

```bash
npm ci
```

## 四、配置生产后台地址

当前终端执行：

```bash
export VITE_API_BASE_URL="https://你的域名/api/v1"
```

确认地址：

```bash
echo "$VITE_API_BASE_URL"
```

必须是：

- 完整 `https://` 地址。
- 以 `/api/v1` 结尾。
- 不能写 `127.0.0.1` 或 `localhost`。
- 域名证书有效，手机 Safari 能正常打开。

注意：`VITE_API_BASE_URL` 是构建时变量。修改后必须重新执行 H5 构建并同步 iOS 工程，否则 App 仍会使用旧地址。

## 五、生成并同步 iOS 工程

在 `mobile-app` 目录执行：

```bash
npm run build:h5
npx cap sync ios
```

检查有没有报错。同步完成后打开 Xcode：

```bash
npx cap open ios
```

如果命令无法打开，也可以执行：

```bash
open ios/App/App.xcodeproj
```

每次修改 Vue/uni-app 页面、接口地址或前端依赖后，都要重新执行：

```bash
npm run build:h5
npx cap sync ios
```

只改 Xcode 原生配置时，不需要重新构建 H5。

## 六、Xcode 里配置应用身份

### 1. 选择工程和 Target

在 Xcode 左侧点击蓝色工程 `App`，在中间选择 `TARGETS → App`。

### 2. 设置 Team 和 Bundle ID

进入 `Signing & Capabilities`：

1. 勾选 `Automatically manage signing`。
2. 在 `Team` 选择你的 Apple Developer Team。
3. 检查 `Bundle Identifier`。

当前值是：

```text
com.shangban.assetlibrary
```

如果这个 Bundle ID 已被其他账号占用，必须换成一个你自己的唯一反向域名，例如：

```text
com.yourcompany.assetlibrary
```

同时修改：

- Xcode 的 `PRODUCT_BUNDLE_IDENTIFIER`
- `mobile-app/capacitor.config.js` 中的 `appId`

两处必须一致。App 发布后不要修改 Bundle ID，否则商店会视为另一个 App。

证书导出的 `.p12`、`.cer`、`.mobileprovision` 和 App Store Connect API 的 `.p8` 都属于敏感文件。仓库已忽略这些扩展名，不要把真实证书或私钥上传 GitHub、聊天群或网盘公开链接。

### 3. 检查版本号

在 `General` 中检查：

```text
Version: 1.0
Build: 1
```

每次提交 App Store Connect，`Build` 必须比上一次大。Version 是用户看到的版本号。

### 4. 不要擅自增加无用权限

本项目的 `Info.plist` 已包含：

- 麦克风：用于语音录入。
- 相机：用于拍摄项目和业务材料。
- 相册：用于导入图片。
- 文件共享与原地打开：用于系统文件选择器。

必须保留这些中文用途说明。只有真正使用某权限时才声明，不要为了“以后可能用”增加定位、通讯录、蓝牙等无关权限。

## 七、真机安装与内测

### 1. 连接 iPhone

1. 用数据线连接 iPhone 和 Mac。
2. 在 iPhone 上点“信任此电脑”。
3. iPhone 打开“设置 → 隐私与安全性 → 开发者模式”。
4. 重启手机并确认开启开发者模式。
5. 在 Xcode 顶部设备列表选择你的 iPhone。

### 2. 选择签名方式

- 只做本机短期调试：可选择 Personal Team。
- 要给别人用 TestFlight：选择正式 Apple Developer Team。
- 如果 Xcode 显示设备不受支持，升级 iOS 或 Xcode 后重试。

### 3. 运行

点击 Xcode 的 Run 按钮。首次安装后，如果系统阻止打开，进入：

```text
设置 → 通用 → VPN 与设备管理
```

信任对应开发者证书。

### 4. iPhone 真机必测

- 首次登录是否能输入邀请码，键盘不遮挡按钮。
- Safari 和 App 都能打开 `/api/v1/health`。
- 首次录音会弹出麦克风权限。
- 说完再点一次能停止，后台 ASR 有返回文字。
- 听不清或识别失败时，提示能区分静音、识别为空和网络错误。
- 拍照、相册、任意文件导入都能选择原件。
- 图片、PDF、Excel、文本和音视频原件可以再次打开。
- 项目买卖、企业租赁、工作记录、个人灵感能新增和回看。
- 关联记录候选可以确认关联、打开和取消。
- 今日待办弹框能显示。
- 创建提醒后，App 退到后台仍能收到本地通知。
- 修改计划状态后，对应提醒会取消或更新。
- 普通成员不能看到他人的私有工作记录和个人灵感。
- 断网、服务器停止和 Key 错误时有可理解提示，不丢失已填写内容。

## 八、准备正式上架材料

### 1. App Store Connect 创建应用

登录 App Store Connect，完成 Developer Program 协议、税务和收款信息中当前要求的部分。

创建新 App，填写：

- 平台：iOS
- 名称：Sayo Sense
- 主要语言：简体中文
- Bundle ID：与 Xcode 完全一致
- SKU：团队内部唯一编号，例如 `SHANGHAI-ASSET-LIBRARY-001`
- 用户访问权限：按团队情况选择

名称和图标不能侵犯他人在先权利。

### 2. 图标和截图

准备：

- App Store 要求的 1024 × 1024 图标，不能带透明通道。
- 当前 App Store Connect 要求的 iPhone 截图尺寸。
- 如支持 iPad，还要准备 iPad 截图。
- 真实功能截图，不要放无法在 App 中复现的页面。

必须替换默认 Capacitor 图标和启动图后再正式提交。

### 3. 隐私政策

隐私政策页面应公网可访问，并真实说明：

- 收集设备 ID、邀请码身份和权限角色。
- 保存业务记录、计划、资料元数据和用户主动上传的原件。
- 音频会上传到团队自己的后台进行识别。
- 识别出的文本可能发送给 DeepSeek 做纠错、分类、计划拆分和关联建议。
- 图片、扫描 PDF 和办公文档会在后台尝试 OCR 或正文提取。
- 相机、相册、麦克风和文件选择的用途。
- 数据保存在团队自己的云服务器和备份介质。
- 数据保留期限、删除方式、联系人、投诉和安全措施。
- 是否将数据用于广告、画像或出售。不能隐瞒真实用途。

不要写“绝不收集任何数据”。本应用明显收集设备标识、语音转写和业务资料。

### 4. App Privacy 数据声明

在 App Store Connect 的 App Privacy 中按实际情况填写，包括：

- 用户内容
- 音频数据
- 照片或视频
- 文件
- 设备 ID
- 诊断或日志
- 是否与用户身份关联
- 是否用于追踪

DeepSeek 或其他外部模型服务是否构成“第三方广告/追踪”要按真实用途判断，不要把业务处理虚报成追踪，也不要漏报数据外发。

### 5. 审核测试资料

App 使用邀请码登录时，审核员没有邀请码就无法验收。请在审核备注中提供：

- 专用审核邀请码。
- 邀请码有效期。
- 可查看的测试数据和测试步骤。
- 生产后台地址。
- 遇到权限弹窗时应允许哪些权限。

建议专门创建有效期较短、使用次数有限的审核邀请码，不要使用生产管理员初始邀请码，也不要提供真实客户资料。

审核完成后可停用审核码。

## 九、制作测试版 TestFlight

### 1. Archive

1. Xcode 顶部设备选择 `Any iOS Device (arm64)`。
2. 菜单选择 `Product → Archive`。
3. 编译完成后，Organizer 自动打开。
4. 选择最新 Archive，点击 `Distribute App`。
5. 选择 `App Store Connect`。
6. 选择 `Upload`。
7. 保持自动签名，按默认选项继续。
8. 上传成功后等待 App Store Connect 处理。

不要选择 `Development` 或 `Ad Hoc` 来代替 App Store Connect 上传。

### 2. 处理合规问题

Xcode 或 App Store Connect 可能询问加密出口合规。

如果应用只使用系统 HTTPS、标准加密库，没有自研或非豁免加密算法，可按真实情况选择常见豁免。若使用了其他加密功能，必须如实说明。不能为了快速提交而随意填写。

### 3. 添加 TestFlight 测试人员

进入 App Store Connect：

1. 打开应用。
2. 进入 `TestFlight`。
3. 等待构建状态从 Processing 变为 Ready to Submit。
4. 填写测试信息、联系邮箱和审核备注。
5. 先添加 Internal Testers。
6. 外部测试人员通常还需要 Beta App Review。

测试人员安装 TestFlight，用 Apple ID 接受邀请后安装应用。

TestFlight 适合内测，但构建会过期，不能当作永久分发渠道。

## 十、提交 App Store 审核

### 1. 创建版本

在 App Store Connect 的 App Store 页面创建新版本，填写：

- 新功能说明
- 推广文本
- 描述
- 关键词
- 支持 URL
- 隐私政策 URL
- 分级问卷
- App Privacy
- 价格和销售范围
- 审核联系人
- 审核备注
- 专用测试邀请码
- 构建版本

### 2. 检查中国大陆区要求

如选择在中国大陆区上架，还要按 Apple 和监管部门当期要求准备 APP 备案、主体信息、内容合规等材料。具体以 App Store Connect 当前提示和主管部门要求为准。

### 3. 提交

选择构建版本后点击 `Add for Review`，再提交。

常见审核状态：

- Waiting for Review：等待审核。
- In Review：审核中。
- Rejected：被拒，需要按 Resolution Center 说明修改或申诉。
- Pending Developer Release：审核通过，等待你手动发布。
- Ready for Sale：已上架。

审核期间保持审核邀请码和测试后台可用。

## 十一、WebView 套壳审核风险

本项目外层是 Capacitor，加载的是本地打包的 uni-app 页面。Apple 审核指南 4.2 可能关注“功能是否足够像原生 App”，而不是单纯网页套壳。

当前可以作为真实功能的证据包括：

- 麦克风录音和上传识别。
- 相机、相册和系统文件导入。
- iOS 本地通知和计划提醒。
- 设备邀请码身份与团队权限。
- 跨模块关联、历史资料和业务记录。
- 离线草稿和同步逻辑（必须真实验收）。
- 原生分享、文件打开和后台提醒能力。

但“用了 Capacitor”本身不等于一定过审。提交前要确保：

- 首次打开不是只有一张网页或宣传页。
- 无网络时不是完全白屏。
- 权限、通知和文件功能在真机可用。
- 审核员能完成至少一条完整业务流程。
- 审核备注说明这是团队业务工具，不是公开网站导航包。
- 不隐藏功能、不绕过 App 内购买规则。

如果公开 App Store 审核风险较高，可以先用 TestFlight 内部验证；长期内部使用可评估 Apple Business Manager 的 Custom Apps 或 Unlisted App Distribution。

## 十二、以后更新版本

每次更新按下面顺序：

1. 先备份云服务器数据库和上传原件。
2. 执行数据库增量迁移。
3. 发布并验证后端。
4. 修改 `Version` 和 `Build`。
5. 在 Mac 重新设置生产地址。

```bash
cd ~/Projects/asset-library/mobile-app
export VITE_API_BASE_URL="https://你的域名/api/v1"
npm ci
npm run build:h5
npx cap sync ios
npx cap open ios
```

6. 真机回归录音、文件、关联和提醒。
7. 重新 Archive。
8. 先上传 TestFlight 验证。
9. 再提交 App Store。

Build 号不能重复。后端和 App 的更新要兼容旧版本，不要先删除字段再通知用户升级。

## 十三、常见问题

### 1. App 登录显示 request:fail

先在 iPhone Safari 打开：

```text
https://你的域名/api/v1/health
```

如果 Safari 也打不开，先修域名、证书、服务器或防火墙。

如果 Safari 能打开但 App 不行，检查：

- `VITE_API_BASE_URL` 是否在 `npm run build:h5` 前设置。
- 是否执行了 `npx cap sync ios`。
- 服务器 `CORS_ORIGINS` 是否包含 `capacitor://localhost`。
- 后台是否重启。
- 是否误用了 `http://`。

### 2. Xcode 提示 Signing for App requires a development team

进入 `Signing & Capabilities`，选择 Team。确认 Apple ID 已加入 Developer Program，且 Bundle ID 未被其他账号占用。

### 3. 无法选择真机

检查：

- iPhone 已信任 Mac。
- 已开启开发者模式。
- Xcode 已安装对应 iOS 支持组件。
- 数据线能传数据，不只是充电。
- iPhone 系统版本高于或等于项目最低 iOS 15。

### 4. 录音没有声音

- iPhone 设置中确认 App 有麦克风权限。
- 先用系统录音机测试硬件。
- 检查 App 是否真的停止录音并上传。
- 查看服务器 `docker compose logs -f backend`。
- 检查 SenseVoiceSmall 模型是否已下载，ASR 状态是否正常。

### 5. 文件选择器打不开

- 确认已重新 `npx cap sync ios`。
- 用真机测试，不只使用模拟器。
- 检查 `Info.plist` 的文件共享配置是否被误删。
- 检查所选文件是否被 iCloud 正常下载到本机。

### 6. TestFlight 看不到构建

- 等待 App Store Connect 完成 Processing。
- 检查 Xcode 上传日志是否成功。
- 检查 Build 号是否重复。
- 检查 Apple Developer 协议、税务或合规提示是否未完成。
- 检查 Apple ID 是否在测试人员名单中。

### 7. 通知不出现

- 首次创建提醒时允许通知。
- 在 iPhone 设置中检查“通知 → Sayo Sense”。
- 检查 App 是否设置为允许后台活动。
- 本地通知不应依赖远程推送证书，但真机必须完成权限和调度验收。
- TestFlight 与 Xcode 调试包的权限表现可能不同，最终以 TestFlight 包验收为准。

### 8. App Store 被拒 4.2

不要只回复“这是我们的业务系统”。应在 Resolution Center 具体说明并演示：

- 原生录音和后台识别。
- 文件与相机能力。
- 本地通知。
- 权限和团队协作。
- 完整业务闭环。

同时检查是否存在白屏、无效按钮、示例数据和审核入口不足。必要时先做 TestFlight 内测，完善产品后再提交公开审核。
