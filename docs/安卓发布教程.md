# Android 内测与正式发布教程

这份教程对应包名：

```text
com.shcredible.sayo
```

包名一旦在应用商店发布，后续不要随便修改，否则商店会把它当成另一个应用。

> 当前项目办理的是腾讯云 APP 备案。正式备案取值请同时阅读：[腾讯云 APP 备案操作](./腾讯云APP备案操作.md)。

## 一、先完成后台部署

Android 包必须连接一个真实 HTTPS 地址，例如：

```text
https://app.sh-credible.com/api/v1
```

请先完成《云端部署教程》，并确认手机浏览器能打开：

```text
https://app.sh-credible.com/api/v1/health
```

同时确认服务器 `.env` 的 `CORS_ORIGINS` 包含：

```dotenv
CORS_ORIGINS=https://app.sh-credible.com,https://localhost,capacitor://localhost
```

## 二、安装 Android 开发环境

在 Windows 电脑上安装：

1. Android Studio
2. Android SDK
3. Android SDK Platform-Tools
4. JDK 21

Android Studio 第一次启动后，在 SDK Manager 中安装当前稳定版 Android SDK 和 Build Tools。

检查 Java：

```powershell
java -version
```

如果 Android Studio 自带 JDK，可以在 Android Studio 的 Gradle 设置中指定它。

## 三、第一次生成调试安装包

### 1. 进入项目

```powershell
Set-Location 'D:\product\made from codex\写字楼业务信息管理App开发计划\mobile-app'
```

如果你的项目在别的目录，换成实际路径。

### 2. 设置后台地址

```powershell
$env:VITE_API_BASE_URL = 'https://app.sh-credible.com/api/v1'
```

这个变量只影响当前 PowerShell 窗口。关掉窗口后需要重新设置。

不要把地址写成：

```text
http://127.0.0.1:8000/api/v1
```

真实手机上的 `127.0.0.1` 指手机自己，不是你的电脑或云服务器。

### 3. 安装依赖

```powershell
npm.cmd ci
```

### 4. 构建 H5 并同步 Android 工程

```powershell
npm.cmd run native:sync:android:debug
```

### 5. 生成 Debug APK

```powershell
npm.cmd run native:build:android:debug
```

> Debug APK 只用于内测和排查问题，不能作为腾讯云 APP 备案的正式签名依据。备案请使用 [腾讯云 APP 备案操作](./腾讯云APP备案操作.md) 中的 Release 签名流程。

Debug APK 路径：

```text
mobile-app\android\app\build\outputs\apk\debug\app-debug.apk
```

### 6. 安装到 Android 手机

手机开启开发者选项和 USB 调试，然后用数据线连接电脑：

```powershell
adb devices
adb install -r '.\android\app\build\outputs\apk\debug\app-debug.apk'
```

如果 `adb` 不在 PATH，使用 Android SDK 的完整路径，或在 Android Studio 的 Terminal 中执行。

### 7. 真机必测清单

- 输入邀请码登录。
- 浏览器打不开时，App 是否给出明确网络提示。
- 首次录音是否弹出麦克风权限。
- 说完后再按一次能停止，并得到识别文字。
- DeepSeek 未配置时，本地整理是否仍可保存。
- 拍照、相册、任意文件导入。
- PDF、Excel、图片、文本原件打开。
- 今日待办弹框。
- 创建提醒后，退到后台是否仍能收到本地通知。
- 买卖、租赁、工作、灵感四类记录。
- 关联记录建议、确认关联、取消关联。

## 四、准备正式签名密钥

签名密钥决定后续能不能升级同一个应用。丢失后通常不能再用原应用更新。

### 1. 创建 keystore

在：

```text
mobile-app\android
```

目录执行：

```powershell
keytool -genkeypair -v `
  -keystore sayo-sense-release.jks `
  -alias sayo-sense-release `
  -keyalg RSA `
  -keysize 2048 `
  -validity 10000
```

执行时会要求填写：

- keystore 密码
- 姓名或组织名称
- 城市
- 省份
- 国家代码，例如 `CN`
- key 密码

密码要保存到可信密码管理器。

### 2. 创建签名配置

复制：

```powershell
Copy-Item '.\keystore.properties.example' '.\keystore.properties'
notepad '.\keystore.properties'
```

填写真实密码：

```properties
storeFile=sayo-sense-release.jks
storePassword=你的keystore密码
keyAlias=sayo-sense-release
keyPassword=你的key密码
```

注意：

- `keystore.properties` 已加入 `.gitignore`。
- `.jks` 已加入 `.gitignore`。
- 不要把这两个文件发给普通成员，不要上传 GitHub。
- 至少做两份离线备份，并记录密码。

腾讯云备案需要的公钥和签名 MD5，按 [腾讯云 APP 备案操作](./腾讯云APP备案操作.md) 从最终 Release APK 中提取。

## 五、修改版本号

每次向商店上传新版本，都必须增加版本号。

编辑：

```text
mobile-app\android\app\build.gradle
```

找到：

```gradle
versionCode 1
versionName "1.0"
```

例如第二个内测版本改为：

```gradle
versionCode 2
versionName "1.0.1"
```

规则：

- `versionCode` 必须是整数，并且每次上传递增。
- `versionName` 是给用户看的版本号。

## 六、生成正式签名的 AAB

Google Play 当前主要使用 Android App Bundle（`.aab`）。

### 1. 重新注入生产后台地址

```powershell
Set-Location 'D:\product\made from codex\写字楼业务信息管理App开发计划\mobile-app'
$env:VITE_API_BASE_URL = 'https://app.sh-credible.com/api/v1'
npm.cmd ci
npm.cmd run build:h5
npx cap sync android
```

### 2. 构建 AAB

```powershell
Set-Location '.\android'
.\gradlew.bat bundleRelease
```

正式 AAB 路径：

```text
mobile-app\android\app\build\outputs\bundle\release\app-release.aab
```

### 3. 生成正式 APK

如果国内商店或内测平台要求 APK：

```powershell
.\gradlew.bat assembleRelease
```

APK 路径：

```text
mobile-app\android\app\build\outputs\apk\release\app-release.apk
```

### 4. 检查签名

```powershell
apksigner verify --verbose '.\app\build\outputs\apk\release\app-release.apk'
```

看到 `Verifies` 即签名有效。

## 七、Android 内测分发

内测不必一开始就上架商店，可以先选择：

1. 直接安装签名 APK。
2. 企业微信、钉钉或网盘分发给固定测试人员。
3. Google Play 内部测试或封闭测试。
4. 国内应用市场内测通道。

内测前给测试人员说明：

- 测试数据可能被清理，但正式上线后不要清空生产数据库。
- 不要上传无关的个人隐私材料。
- 语音会发送到后台识别，部分文本可能发送到 DeepSeek 纠错。
- 遇到问题要记录手机型号、系统版本、时间和操作步骤。

## 八、Google Play 上架步骤

### 1. 注册开发者账号

进入 Google Play Console，注册开发者账号并完成身份验证。

### 2. 创建应用

填写：

- 应用名称：Sayo Sense
- 默认语言：简体中文
- 应用类型：应用
- 免费或付费
- 包名：`com.shcredible.sayo`

包名必须与 `build.gradle` 完全一致。

### 3. 完善商店资料

通常需要：

- 512 × 512 应用图标
- 至少 2 张手机截图
- 简短说明
- 完整说明
- 隐私政策 URL
- 客服支持 URL
- 应用分类
- 联系方式

隐私政策要明确说明：

- 收集设备标识、邀请码身份、业务记录和上传资料。
- 麦克风用于语音录入。
- 相机和相册用于拍项目照片、凭证和资料。
- DeepSeek 可能用于纠错、分类和计划拆分。
- 数据存储在你自己的云服务器。
- 删除和备份策略。

### 4. 填写 Data Safety

必须按真实情况填写：

- 设备 ID
- 音频
- 照片和视频
- 文件
- 工作记录和业务信息
- 是否加密传输
- 是否可以请求删除

不要为了快速过审填写不真实的数据收集声明。

### 5. 设置测试

首次发布建议选择：

- Internal testing：内部测试，最快。
- Closed testing：指定测试人员。
- Open testing：公开测试。

上传 `app-release.aab`，添加测试人员邮箱，等待 Google 审核测试版本。

### 6. 正式生产发布

测试通过后：

1. 创建生产版本。
2. 上传新 AAB。
3. 填写发布说明。
4. 提交审核。
5. 审核通过后选择自动发布或手动发布。

以后更新必须使用同一个包名和同一个签名体系。

## 九、国内 Android 商店

常见渠道：

- 华为应用市场
- 小米应用商店
- OPPO 软件商店
- vivo 应用商店
- 应用宝

每个渠道要求不同，常见材料包括：

- 企业开发者认证
- 软件著作权或相关权属证明
- 隐私政策
- 权限说明
- 签名 APK 或 AAB
- 应用截图和介绍
- ICP 备案信息

国内商店通常审核更重视：

- 麦克风、相册、文件权限是否与功能一致。
- 是否首次启动就索取无关权限。
- 隐私政策是否可访问。
- 是否有账号注销或数据删除渠道。
- 是否存在 WebView 套壳、功能不足问题。

如果被判定为简单网页套壳，需要准备功能说明，强调原生录音、文件导入、本地通知、设备邀请码、安全文件访问等原生能力。

## 十、更新版本

每次更新：

1. 后端先完成备份和数据库迁移。
2. 确认生产域名可访问。
3. 增加 `versionCode` 和 `versionName`。
4. 重新设置 `VITE_API_BASE_URL`。
5. 执行：

```powershell
npm.cmd run build:h5
npx cap sync android
Set-Location '.\android'
.\gradlew.bat bundleRelease
```

6. 在测试轨道安装验证。
7. 再提交正式审核。

## 十一、常见问题

### 1. App 显示 request:fail

先在手机浏览器打开：

```text
https://app.sh-credible.com/api/v1/health
```

打不开时先修服务器，不要反复改邀请码。

### 2. 登录后马上掉线

检查：

- `PUBLIC_BASE_URL` 是否是 HTTPS 域名。
- `CORS_ORIGINS` 是否包含 `https://你的域名,https://localhost,capacitor://localhost`。
- 手机是否真的能访问服务器。
- 系统时间和时区是否正确。

### 3. 录音没有声音

- 在系统设置中确认 App 有麦克风权限。
- 先用手机自带录音机确认麦克风硬件正常。
- 再检查后端 ASR 日志。

### 4. 文件选择器打不开

- 检查 Android 系统文件权限。
- 用真实手机测试，不仅用模拟器。
- 检查 Capacitor 同步是否执行过。

### 5. Release 构建提示没有签名

- 确认 `mobile-app/android/keystore.properties` 存在。
- 确认 `storeFile` 指向的 `.jks` 文件存在。
- 确认密码没有多余空格。

### 6. 安装时提示签名冲突

手机上已有另一个签名的同包名 App。先卸载测试版，再安装新签名包。正式用户不能通过卸载解决，所以正式发布后必须永久保管同一个签名密钥。

## 十二、发布前检查

- [ ] `VITE_API_BASE_URL` 是生产 HTTPS 地址。
- [ ] 包名未改。
- [ ] `versionCode` 已递增。
- [ ] Release AAB/APK 已用正式密钥签名。
- [ ] keystore 和密码已离线备份。
- [ ] 真机麦克风、文件、通知验收通过。
- [ ] 隐私政策 URL 可访问。
- [ ] Data Safety 填写真实。
- [ ] 测试邀请码和测试账号准备完成。
- [ ] 后端已备份。
- [ ] 已知问题已写入发布说明。
