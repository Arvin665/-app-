# 商办信息资产库：云服务器部署教程

这份教程面向第一次部署网站的开发小白。按顺序执行即可，不要跳步。

教程以 Ubuntu 24.04 LTS、一个域名、单台云服务器为例。最终结构是：

```text
用户浏览器 / Android / iOS
            │
         HTTPS 443
            │
       Caddy（宿主机）
            │
  127.0.0.1:8080
            │
   Nginx（Docker 内）
     ├─ H5 静态页面
     └─ /api -> FastAPI
                    │
          ├─ MySQL 8（Docker Volume）
          ├─ Redis 7（Docker Volume）
          └─ /app/uploads（Docker Volume）
```

## 一、先准备什么

### 1. 服务器建议

内测阶段建议：

- CPU：4 核
- 内存：8 GB
- 系统盘：100 GB SSD
- 系统：Ubuntu 24.04 LTS
- 带宽：5 Mbps 起步

原因：

- SenseVoiceSmall 本地语音识别会占 CPU 和内存。
- OCR、扫描 PDF 也会占 CPU。
- Docker 首次构建还要下载 Python、Node、FFmpeg 和语音模型，磁盘会明显增长。

如果团队人数较多、上传文件很多，建议升到 8 核 16 GB，并单独增加数据盘。

### 2. 域名与备案

- 中国大陆服务器：网站域名通常需要 ICP 备案，未备案可能被服务商阻断 80/443 端口。
- 中国香港、新加坡服务器：一般不需要大陆 ICP 备案，但国内访问速度、数据合规要求要另行评估。
- 域名 DNS 需要添加一条 `A` 记录，指向服务器公网 IPv4。

例如：

```text
主机记录：app
记录类型：A
记录值：你的服务器公网 IP
最终域名：app.example.com
```

在本地电脑检查解析：

```bash
nslookup app.example.com
```

解析结果应显示服务器公网 IP。

### 3. 云安全组和防火墙

只开放以下端口：

| 端口 | 用途 |
| --- | --- |
| 22 | SSH 管理 |
| 80 | HTTP，Caddy 申请 HTTPS 证书 |
| 443 | HTTPS |

不要对公网开放：

- `3306`：MySQL
- `6379`：Redis
- `8000`：FastAPI
- `8080`：内部 Web 容器

## 二、登录服务器并安装运行环境

### 1. 登录服务器

在你的电脑终端执行：

```bash
ssh root@你的服务器公网IP
```

如果是普通用户：

```bash
ssh ubuntu@你的服务器公网IP
```

### 2. 更新系统

```bash
sudo apt update
sudo apt upgrade -y
sudo apt install -y ca-certificates curl git nano ufw unzip
```

设置上海时区：

```bash
sudo timedatectl set-timezone Asia/Shanghai
date
```

### 3. 安装 Docker 和 Docker Compose

使用 Docker 官方安装脚本：

```bash
curl -fsSL https://get.docker.com -o /tmp/get-docker.sh
sudo sh /tmp/get-docker.sh
sudo systemctl enable --now docker
```

检查版本：

```bash
docker --version
docker compose version
```

运行测试容器：

```bash
sudo docker run --rm hello-world
```

为了让备份脚本可以直接运行，可以把当前用户加入 Docker 用户组：

```bash
sudo usermod -aG docker $USER
newgrp docker
docker ps
```

如果 `newgrp` 后仍提示权限不足，退出 SSH 再重新登录。

### 4. 安装 Caddy

```bash
sudo apt install -y caddy
sudo systemctl enable --now caddy
sudo systemctl status caddy --no-pager
```

Caddy 负责自动申请和续期 HTTPS 证书。

### 5. 开启防火墙

```bash
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status
```

云厂商控制台的“安全组”也要只放行 22、80、443。

## 三、下载项目并填写生产配置

### 1. 下载项目

```bash
sudo mkdir -p /opt/asset-library
sudo chown -R $USER:$USER /opt/asset-library
cd /opt/asset-library
git clone https://github.com/Arvin665/-app-.git .
```

如果目录不是空的，先确认里面没有你自己的文件，再选择其他空目录。

`git clone` 只会下载已经推送到 GitHub 的最新提交。如果 Windows 本地还有未提交改动，先在本地项目目录检查并上传：

```powershell
git status --short
# 只添加本次需要发布的源码和文档，不要提交 .env、keystore.properties、.jks 或用户上传文件
git add <需要发布的文件>
git commit -m "准备部署内测"
git push origin master
```

如果本地 `git status` 列出的内容很多，先让开发人员逐项确认，不要直接 `git add -f` 强制上传被忽略的密钥文件。

### 2. 创建生产 `.env`

```bash
cp deploy/.env.production.example .env
nano .env
```

至少修改下面这些值：

```dotenv
MYSQL_ROOT_PASSWORD=一段很长的数据库根密码
MYSQL_PASSWORD=一段很长的应用数据库密码
SENSITIVE_FIELD_KEY=一段至少32位的随机密钥
BOOTSTRAP_INVITE_CODE=六位数字
PUBLIC_BASE_URL=https://你的域名
CORS_ORIGINS=https://你的域名,https://localhost,capacitor://localhost
DEEPSEEK_API_KEY=你的真实Key
```

生成随机密码和密钥：

```bash
openssl rand -base64 48
openssl rand -base64 48
openssl rand -base64 48
```

生成六位数字初始邀请码：

```bash
shuf -i 100000-999999 -n 1
```

必须注意：

- `PUBLIC_BASE_URL` 必须是最终 HTTPS 域名，最后不要带 `/`。
- `CORS_ORIGINS` 使用英文逗号分隔。
- `CORS_ORIGINS` 必须保留 `https://localhost`（Android 容器）和 `capacitor://localhost`（iOS 容器），否则原生 App 可能出现登录 `request:fail`。
- `DEEPSEEK_API_KEY` 只能放在服务器 `.env`，不能放进前端代码或提交 Git。
- `.env` 已在 `.gitignore` 中，不要强制提交。
- `SENSITIVE_FIELD_KEY` 后续不要随便更换，否则佣金等加密字段可能无法解密。

DeepSeek 建议先使用服务商控制台当前可用的通用对话模型标识。模板默认值：

```dotenv
AI_PROVIDER=auto
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_TIMEOUT_SECONDS=90
```

不要写反斜杠 `\`。`deepseek-chat` 是否仍是最新版本，以 DeepSeek 控制台和官方文档当前模型列表为准；模型名写错时后端会自动降级到本地规则，并在接口状态中显示调用失败原因。

### 3. 检查 Compose 配置

```bash
docker compose config
```

如果提示缺少变量，说明 `.env` 没填完整。

## 四、初始化或升级数据库

这是最关键的步骤。

### 情况 A：全新的空数据库

不需要手动导入。第一次执行 `docker compose up` 时，MySQL 容器会自动读取：

```text
backend/app/database/init.sql
```

并创建全部表。

### 情况 B：数据库里已经有业务数据

不要再次执行 `init.sql`。该文件包含 `DROP TABLE`，重复执行会清空旧表。

先备份，再单独执行增量迁移：

```bash
docker compose up -d mysql
docker compose exec -T mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines --events "$MYSQL_DATABASE"' > before_migration_$(date +%Y%m%d_%H%M%S).sql
```

再导入跨模块关联表迁移：

```bash
docker compose exec -T mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"' < backend/app/database/migrations/20261119_add_record_links.sql
```

确认表已存在：

```bash
docker compose exec -T mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE" -e "SHOW TABLES LIKE '\''sys_record_link'\'';"'
```

看到 `sys_record_link` 即成功。

如果你不确定当前数据库是不是空库，先按“情况 B”备份和迁移，不要直接删除 Docker Volume。

## 五、构建并启动完整服务

### 1. 首次构建

```bash
cd /opt/asset-library
docker compose up -d --build
```

首次构建时间可能较长，因为系统需要：

- 安装后端 Python 依赖。
- 安装 FFmpeg、OCR 依赖。
- 下载 SenseVoiceSmall 和 Vosk 模型。
- 构建移动端 H5。

### 2. 查看状态

```bash
docker compose ps
```

`mysql`、`redis`、`backend`、`web` 最终都应为 `running` 或 `healthy`。

查看后端日志：

```bash
docker compose logs -f backend
```

按 `Ctrl+C` 退出日志查看，不会停止服务。

单独检查本机入口：

```bash
curl http://127.0.0.1:8080/api/v1/health
```

正常结果应包含：

```json
{"status":"ok","database":"ok"}
```

Redis 如果显示 `unavailable`，先执行：

```bash
docker compose restart redis backend
docker compose logs --tail=100 redis
```

## 六、配置域名 HTTPS

### 1. 复制 Caddy 配置

```bash
sudo cp /opt/asset-library/deploy/Caddyfile.example /etc/caddy/Caddyfile
sudo nano /etc/caddy/Caddyfile
```

把里面的：

```text
app.example.com
```

改成你的真实域名。

### 2. 检查并重载

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
sudo systemctl status caddy --no-pager
```

### 3. 验证 HTTPS

```bash
curl -I https://你的域名
curl https://你的域名/api/v1/health
```

如果证书申请失败，重点检查：

- 域名 A 记录是否已经指向这台服务器。
- 云安全组是否放行 80 和 443。
- 服务器 80/443 是否被其他程序占用：

```bash
sudo ss -lntp | grep -E ':80|:443'
```

## 七、首次登录和管理员邀请码

打开：

```text
https://你的域名
```

首次登录使用 `.env` 里的：

```dotenv
BOOTSTRAP_INVITE_CODE=你的六位数字
```

首个管理员绑定成功后，系统会立即停用这个初始管理员邀请码。后续成员必须由管理员在应用内生成新邀请码。

管理员应立即检查：

1. 个人中心能正常打开。
2. 新建设备邀请码，并限制使用次数和有效期。
3. 团队成员用新邀请码绑定。
4. 普通成员看不到他人的私有工作记录和个人灵感。
5. 买卖、租赁、共享工作记录和资料可以正常新增与查看。

## 八、确认 DeepSeek、OCR 和语音识别

### 1. 检查服务状态

```bash
curl -H "X-Device-ID: 你的32位设备ID" https://你的域名/api/v1/ai/status
```

普通浏览器可以先登录，再从应用网络请求中查看设备 ID。不要把自己的设备 ID 公开发布。

重点字段：

- `deepseek_configured: true`：后端已读取到 Key。
- `deepseek_configured: false`：`.env` 没有正确填写，或容器没有重启。
- `ocr.enabled: true`：OCR 服务已开启。
- ASR 状态显示 `sensevoice` 或可用模型：本地语音识别已就绪。

修改 `.env` 后必须重启：

```bash
cd /opt/asset-library
docker compose up -d --force-recreate backend
docker compose logs --tail=100 backend
```

### 2. 手动做三次验收

1. 说一段企业租赁信息，确认 ASR 能把文字显示在确认框中，再确认 DeepSeek 是否被调用。
2. 上传一张带文字的图片，确认原件保存成功，并查看 OCR 状态。
3. 上传一个 Excel 或 PDF，确认原件、正文预览和检索结果都能回看。

如果 DeepSeek 失败，本地规则仍应能生成候选结果；不能让整次录入丢失。

## 九、数据是怎么保存的

Docker Compose 使用三个持久化 Volume：

| Volume | 内容 |
| --- | --- |
| `mysql_data` | 全部业务记录、用户设备、邀请码、操作日志、记录关联 |
| `redis_data` | 登录缓存和可重建的临时缓存 |
| `uploads_data` | 所有原件、缩略图、扫描件和音视频 |

重要规则：

- 不要执行 `docker compose down -v`，`-v` 会删除 Volume。
- 普通停止使用 `docker compose down`，数据会保留。
- 普通重启使用 `docker compose restart`。
- 更新镜像使用 `docker compose up -d --build`。
- 修改代码前先备份。

跨模块关系保存在 `sys_record_link`。系统只给出“可能相关”建议，用户在详情页点击确认后才真正建立关联，避免同名楼宇或企业被自动错连。

## 十、备份

### 1. 立即手动备份一次

```bash
cd /opt/asset-library
chmod +x scripts/backup.sh
./scripts/backup.sh
```

脚本会生成：

```text
backups/database_日期时间.sql
backups/uploads_日期时间.tar.gz
```

### 2. 每天自动备份

编辑定时任务：

```bash
crontab -e
```

加入一行：

```cron
30 2 * * * cd /opt/asset-library && ./scripts/backup.sh >> $HOME/asset-library-backup.log 2>&1
```

检查日志：

```bash
tail -n 100 $HOME/asset-library-backup.log
```

### 3. 异地备份

只把备份放在同一台服务器不算安全备份。服务器磁盘损坏时会一起丢失。

至少选择一种：

- 云厂商对象存储，开启版本控制。
- 另一台云服务器。
- 加密后同步到可信的网盘。

建议保留：

- 最近 30 天每日备份。
- 每月一份长期备份。
- 每次升级前一份手动备份。

### 4. 恢复备份

恢复会覆盖现有数据，先在一个测试环境演练。

停止写入：

```bash
cd /opt/asset-library
docker compose stop web backend
```

恢复数据库：

```bash
docker compose exec -T mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"' < backups/database_你的时间.sql
```

恢复上传原件：

```bash
docker compose run --rm -T \
  -v "$PWD/backups/uploads_你的时间.tar.gz:/tmp/uploads.tar.gz:ro" \
  backend sh -c 'rm -rf /app/uploads/* && tar -xzf /tmp/uploads.tar.gz -C /app'
```

重新启动：

```bash
docker compose up -d
curl https://你的域名/api/v1/health
```

恢复后抽查：

- 业务记录数量和抽样内容。
- 交易佣金权限。
- 关联记录。
- 图片、PDF、Excel 原件能否打开。
- 私有工作记录是否仍只对原设备可见。

## 十二、常见问题

### 1. 网站打不开

```bash
docker compose ps
docker compose logs --tail=200 web backend
sudo journalctl -u caddy -n 200 --no-pager
curl http://127.0.0.1:8080/api/v1/health
```

### 2. HTTPS 证书失败

检查：

```bash
nslookup 你的域名
sudo ss -lntp | grep -E ':80|:443'
sudo journalctl -u caddy -n 200 --no-pager
```

### 3. 登录显示 request:fail

在手机浏览器打开：

```text
https://你的域名/api/v1/health
```

如果打不开，是域名、HTTPS、防火墙或后端健康检查问题，不是邀请码问题。

### 4. 上传文件打不开

新版文件通过带有效期的 `/api/v1/files/...` 签名地址读取，不再公开 `/uploads/`。确认：

- `PUBLIC_BASE_URL` 是当前真实 HTTPS 域名。
- 后端已重启。
- 文件仍在 `uploads_data` Volume 内。

### 5. DeepSeek 显示未配置

```bash
cd /opt/asset-library
grep -E '^(AI_PROVIDER|DEEPSEEK_BASE_URL|DEEPSEEK_MODEL)=' .env
docker compose exec backend printenv AI_PROVIDER DEEPSEEK_MODEL
docker compose up -d --force-recreate backend
```

不要把 `DEEPSEEK_API_KEY` 的值输出到聊天、截图或公开日志中。

### 6. 磁盘满了

```bash
df -h
docker system df
docker compose logs --tail=100 backend
```

清理旧镜像前先确认当前容器运行正常：

```bash
docker image prune
```

不要清理 `mysql_data`、`redis_data`、`uploads_data`。
